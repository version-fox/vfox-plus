# Internationalisation

vfox-plus is available in **English** and **Simplified Chinese**. Every
implementation uses the same translation catalogues, so wording stays identical
across technologies and each text is translated once.

## Catalogues

The catalogues are in [`shared/i18n`](../shared/i18n), in the
[Application Resource Bundle](https://github.com/google/app-resource-bundle)
format: JSON files whose messages use
[ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/).

| File          | Locale                          | Role                                       |
| ------------- | ------------------------------- | ------------------------------------------ |
| `app_en.arb`  | `en`                            | Template: every message and its metadata.  |
| `app_zh.arb`  | `zh` (Simplified Chinese, `zh-Hans`) | Translation.                           |

`app_zh.arb` uses the generic `zh` code because it is the only Chinese
catalogue; a Traditional Chinese translation would be added as
`app_zh_Hant.arb`, and `app_zh.arb` stays the fallback for every Chinese locale.

A message in the template looks like this:

```json
"sdksVersionCount": "{count, plural, =0{No version installed} =1{1 version installed} other{{count} versions installed}}",
"@sdksVersionCount": {
  "description": "Number of installed versions of an SDK.",
  "placeholders": { "count": { "type": "int", "example": "3" } }
}
```

Rules:

- Keys are `lowerCamelCase` and start with the area they belong to (`nav…`,
  `home…`, `sdks…`, `sdk…`, `version…`, `available…`, `plugins…`, `task…`,
  `settings…`, `config…`, `about…`, `action…`).
- Every message of the template has a `description` for translators, and every
  placeholder a `type` and an `example`.
- Plurals and selections use ICU syntax; never concatenate translated
  fragments.
- Translations keep every placeholder of the template.
- Texts that are not translated, such as the names of languages (`English`,
  `简体中文`), commands (`vfox activate`) and file names, are not in the
  catalogues.

The Flutter tests (`flutter/test/project_test.dart`) check these rules: same keys
in every catalogue, a description for every message, every placeholder kept.

## Using the catalogues

- **Flutter** generates type-safe accessors with `flutter gen-l10n`, configured
  in [`flutter/l10n.yaml`](../flutter/l10n.yaml) to read `../shared/i18n`. The
  generated code is committed in `flutter/lib/src/l10n` and checked for drift in
  CI.
- The **web front end** bundles the ARB files unchanged (a Vite plugin imports
  them as JSON) and formats them with a small formatter for the subset of ICU
  that the catalogues use: placeholders and plurals with exact matches and
  plural categories (`web/src/core/i18n`). Its tests parse every message and
  check the rules above.
- Other stacks can read ARB directly (it is JSON), or convert it with their
  tooling, for example to Fluent, `.resx`, Android string resources or an i18next
  JSON with ICU support. Converted files are build products and must not be
  committed as sources.

## Choosing the language

The language setting is `system`, `english` or `simplifiedChinese`. With
`system`, the desktop locale is matched against the available catalogues and
English is the fallback; every Chinese locale gets Simplified Chinese.

## Style

- English: sentence case for titles and buttons ("Add plugin", not "Add
  Plugin"); no full stop on labels, a full stop on sentences; "…" for actions
  that ask for more input ("Browse…").
- Chinese: full-width punctuation (，。：？“”（）), a space between Chinese and
  Latin text or numbers (`安装 maven@3.9.16`, `已安装 2 个版本`), and the
  ellipsis `…`.

## Adding a language

1. Copy `shared/i18n/app_en.arb` to `app_<locale>.arb`, set `@@locale` and
   remove the `@` metadata entries.
2. Translate every message; keep placeholders and ICU syntax.
3. Add the language to the language setting of every implementation and to
   [`architecture.md`](architecture.md#settings).
4. Run the tests of every implementation.
