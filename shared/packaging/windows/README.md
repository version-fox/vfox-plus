# Windows packaging (MSIX)

> [简体中文](README.zh-CN.md)

This directory holds the inputs of the Windows packaging of vfox+:
`vfxtool build-msix` turns staged Windows executables into unsigned `.msix`
packages (one per architecture) and a `.msixbundle` for **Windows 11**.

| File | Purpose |
| --- | --- |
| `README.md` | This document (English). |
| `README.zh-CN.md` | Chinese translation. |
| [`Sign-Msix.ps1`](Sign-Msix.ps1) | One-command self-sign and install on Windows 11: creates a self-signed certificate, rebuilds the packages with the matching publisher, signs them with osslsigncode and installs the bundle. |

The package identity, the manifest, the logos and the bundle layout are
generated by `vfxtool build-msix`
(`shared/tooling/internal/buildmsix`); nothing binary is committed here.

## What is built

For each architecture (`x64` for AMD64, `arm64` for ARM64):

- `vfox-plus_<version>_<arch>.msix`: an unsigned OPC ZIP with
  `AppxManifest.xml`, `[Content_Types].xml`, `AppxBlockMap.xml`, the
  executable (for example `vfox-plus.exe`) and the `Assets/` logos.
- `vfox-plus_<version>.msixbundle`: the regular bundle containing the
  `.msix` files with `AppxMetadata/AppxBundleManifest.xml`.

The identity defaults to `dev.vfox.VfoxPlus` (the same as the Linux desktop
entry) and the publisher to `CN=vfox-plus` with the unsigned-package OID
(`OID.2.25.311729368913984317654407730594956997722=1`), which Windows 11
requires for `-AllowUnsigned` installs. The target device family is
`Windows.Desktop` with `MinVersion 10.0.22000.0` (Windows 11).

## Building

Cross-compile on any OS (mygo needs no C compiler), then package:

```sh
vfxtool build --goos windows --goarch amd64 --root mygo stage-x64/vfox-plus.exe
vfxtool build --goos windows --goarch arm64 --root mygo stage-arm64/vfox-plus.exe
SOURCE_DATE_EPOCH="$(git log -1 --format=%ct)" vfxtool build-msix \
  --package vfox-plus --version "$(tr -d '[:space:]' < mygo/VERSION)" \
  --stage-x64 stage-x64 --stage-arm64 stage-arm64 \
  --executable vfox-plus.exe dist
```

Only one `--stage-*` is needed for a single-architecture bundle. The output is
reproducible: ZIP entries are stored (no compression), sorted, with timestamps
from `SOURCE_DATE_EPOCH`.

## Installing on Windows 11

No third-party certificate is needed. Extract the `vfox-plus-windows`
artifact (it holds the unsigned packages, the loose executables, a Windows
`vfxtool.exe` and [`Sign-Msix.ps1`](Sign-Msix.ps1)), then run the script in
PowerShell. It relaunches itself elevated and does everything: create (or reuse)
a self-signed code-signing certificate, rebuild the `.msix`/`.msixbundle` with
the matching publisher, sign them with osslsigncode (downloaded automatically,
no Windows SDK needed), trust the certificate for the local machine and install
the bundle.

```powershell
powershell -ExecutionPolicy Bypass -File Sign-Msix.ps1
```

Re-running is safe: the existing certificate is reused and the install is
repeated. `Sign-Msix.ps1 -SkipInstall` rebuilds and signs without installing;
`-PublisherCN <name>` uses another publisher name; `-Force` creates a fresh
certificate. The script keeps the private key in your own certificate store —
only you can sign with it.

### Manual install (unsigned)

Without signing, the unsigned packages install with `Add-AppxPackage
-AllowUnsigned` in an elevated PowerShell (executable content installs for all
users):

```powershell
Add-AppxPackage -Path .\vfox-plus_0.1.0.msixbundle -AllowUnsigned
```

To run from source without packaging, build on Windows and run the exe
directly.

## Signing notes (for maintainers)

- A signed package's publisher must exactly equal the certificate subject, with
  no OID — which is why the script rebuilds the packages instead of signing the
  unsigned ones in place (their publisher carries the unsigned-package OID).
- A self-signed certificate only convinces machines that trust it, which is
  exactly what the script sets up locally. For public distribution without any
  per-machine step, either publish to the Microsoft Store (Microsoft signs) or
  sign with a publicly trusted code-signing certificate or Azure Trusted
  Signing; the build is the same, only `--publisher` and the signing step
  change.
